# 箱熵知识编译器

解释箱熵系统、比较箱熵与 RAG/传统知识图谱，或把知识编译模式迁移到其他技术领域时，
读取本文件。

## 编译过程

```text
论文、代码仓库、文档、API、模型、数据集与基准
→ 来源获取和证据记录
→ 实体规范化与消歧
→ 以主题为边界的研究和类型化组装
→ 任务链、能力、资产、关系与来源
→ 有界校验、去重、冲突处理与准入
→ 持久化图谱与索引
→ 全景探索、检索、工作流组装和缺口发现
→ 将运行时缺口转化为新的编译目标
```

关键设计不是在每次查询时重新生成结构，而是把可以复用的技术结构持久化。普通 RAG 在
查询时检索片段并生成答案；箱熵把部分推理和工程组织工作前置为类型化知识产物，供之后
的问题和 Agent 反复消费。

## 主要关系类型

- 领域或主题 `contains` 子主题、任务链和实体；
- 任务步骤通过 `next`、`branch` 和 `merge` 表示执行结构；
- 任务步骤 `require` 能力；
- 能力具有父子与依赖关系；
- 资产 `implement` 或被能力和主题 `used_by`；
- 记录通过 `grounded_in` 指向证据和来源文档。

关系不是图上的装饰线。使用关系时应保留方向、来源、版本和可用的校验状态。

## 箱熵不是什么

- 不只是网页目录：资产与能力、任务环境和证据相连。
- 不只是 RAG：持久化图谱在用户提出问题前已经存在。
- 不只是普通知识图谱：它还描述工程路径和可复用能力结构。
- 不是完整机器人执行本体：它不完整描述实时状态、动作语义、物体可供性和安全控制。
- 不是自动产生真理：Agent 可以产生候选，准入、证据、冲突处理和校验决定什么可以进入
  持久知识基座。

## 设计原则

- **事实重于观点**：保留来源、不确定性和负面证据。
- **结构重于收集**：把知识连接成有类型、可使用的关系。
- **组合重于重做**：让能力和资产在不同主题之间复用。
- **先验证，再智能**：生成的结构经过检查后才能被当作持久知识。
- **持续演化，而非整体替换**：增量更新并保留版本和冲突上下文。

把知识编译模式迁移到其他领域时，应先定义那个领域真实稳定的实体、关系、任务结构、
证据规则和准入门，而不是直接复制机器人领域的标签。
