# 具身智能全景图使用指南

领域定位、技术版图分析、主题发现和图谱遍历任务需要读取本文件；简单的精确实体查询不必
加载。

## 图谱层级

| 层级 | 回答的主要问题 |
| --- | --- |
| 领域 Domain | 这个问题属于具身智能的哪个主要部分？ |
| 垂直主题 Topic | 当前要解决的边界清晰的技术问题是什么？ |
| 任务链 Task Chain | 需要哪些步骤、分支和合并？ |
| 能力 Capability | 系统必须能够实现什么？ |
| 资产 Asset | 什么资源可以实现、训练、评测或支撑这项能力？ |
| 依赖 Dependency | 各部分之间存在哪些顺序、接口或前置关系？ |
| 证据 Evidence | 什么来源支持或限定当前技术选择？ |

公开全景图包含基础模型、人机交互、学习与适应、定位、操作、建图与 SLAM、运动与控制、
多机器人系统、导航、感知、规划与决策、推理与智能体、安全与可信、仿真与数字孪生、
系统基础设施15个顶层领域。

## 常用遍历模式

### 领域版图

用户需要了解一个方向时：

1. 选择核心领域以及2至4个相邻领域。
2. 找到各领域中有代表性的垂直主题。
3. 找出跨主题复用的能力。
4. 按作用而不是热度对资产分类。
5. 追踪不同能力和资产组之间的主要依赖。
6. 报告证据覆盖和明显空白。

### 工程路径

用户要建设一个系统时：

1. 把需求映射到一个或多个垂直主题。
2. 检查候选任务链及其分支条件。
3. 解析所需能力和前置依赖。
4. 把能力连接到接口与约束相容的资产。
5. 为关键选择检索证据。
6. 暴露未解决接口和验证门。

### 跨领域依赖图

问题出现在子系统交界处时：

1. 找到发生交接的核心能力。
2. 向上追踪数据、模型、硬件和运行时前置条件。
3. 向下追踪使用者和评测要求。
4. 区分图谱明确记录的依赖和 Agent 推断的关系。
5. 描述连接子系统所需的最小接口契约。

## 推荐输出

全景回答应当有选择地呈现：

- 核心领域与相邻领域；
- 代表性主题；
- 共享能力与瓶颈能力；
- 重要任务链和依赖路径；
- 资产类别及代表实例；
- 证据、冲突和限制；
- 盲区与待解决问题。

图谱规模不能证明图谱正确或完整。节点数量说明知识产物的规模；证据可解析性、语义质量、
覆盖范围和时效性是不同的评价维度。
